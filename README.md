# gg4

This repository produces [main.pdf](main.pdf) and holds the report source, the
analysis code in [submission/](submission/), and the notebooks that build every
figure in [notebooks/](notebooks/).

Start with [main.pdf](main.pdf) for the narrative; this README covers the layout
and how to rebuild from source.

## Getting started

Dependencies and the Python version are managed with
[uv](https://docs.astral.sh/uv/), which is preferred over pip.

1. Install uv, then clone this repository.

2. Sync dependencies from the repository root:

   ```sh
   uv sync
   ```

   This creates a `.venv` and installs the pinned set from `uv.lock` against
   Python 3.12.

3. Install the `Brain` (the `GG4` package). Place your wheels in `wheels/`, then
   run [provided/install.py](provided/install.py):

   ```sh
   cd provided && uv run python install.py
   ```

## Data

The `data/` cache (`.npz`, `.pkl`, and Optuna `.db` studies) is excluded from
version control for its size and is recomputed on demand when a notebook runs.
Email ta549@cam.ac.uk for the precomputed cache.

## How the report is generated

Figures, captions, and tables are generated by notebooks rather than written
into the LaTeX source. For a key `<key>`, the notebook
`notebooks/<key>/<key>.ipynb` exports `figures/<key>.pgf`, `captions/<key>.tex`,
and any table into `tables/`. The report pulls them in with `\pgffigure{<key>}`
(figure, caption, and `fig:<key>` label) and `\latextable{<key>}`. The folder
name, the `.pgf`, the caption, and the macro argument are one and the same
string, so every plot in the PDF traces back to a single notebook. Captions are
written in each notebook's caption cell, not edited under `captions/`.

## The control policy submission

[control_policy.py](control_policy.py) implements the assessed interface,
`control_policy(observations, target)`, as a single file that depends on `numpy`
and `scipy` alone and imports nothing from [submission/](submission). The
observation is the hand position, so `observations[-1]` is the current Cartesian
position and `target` is the goal.

The controller reuses the optimal configuration found by
[cartesian_control_sweep](notebooks/cartesian_control_sweep/cartesian_control_sweep.ipynb),
which drives the brain in open loop (`use_lqi=False`): it sums sinusoids at the
calibrated muscle-selection frequencies and re-solves the per-band amplitudes
from the current posture at every step. That path needs only three results, all
fit on seed 0 and baked into the file as literals: the band frequencies, the
gain matrix, and the Bayesian-optimisation hyperparameters. The identification
matrices the feedback path would use are not required here.

Two scripts accompany the file:

- [extract_seed0_params.py](scripts/extract_seed0_params.py) reprints those
  seed-0 band frequencies, gain matrix, and hyperparameters from the `data/`
  cache, matching the baked-in literals.
- [verify_control_policy.py](scripts/verify_control_policy.py) replays the
  reference controller step by step to confirm the reimplementation is exact,
  then runs the policy in closed loop across seeds 0–4 and cross-checks seed 0
  against the saved optimal results.

```sh
uv run python scripts/extract_seed0_params.py
uv run python scripts/verify_control_policy.py
```

## Tooling

Format, lint, and type-check with:

```sh
uv run ruff format .
uv run ruff check .
uv run ty check
```

Re-running a notebook recomputes its `data/` cache and re-exports its outputs;
the sweeps and robustness studies are expensive and run in parallel. Experiments
follow the honesty principle (no averaging of noise across `Brain` seeds) set out
in the Rules of engagement section of [main.pdf](main.pdf).

## Building the report

The report is typeset with XeLaTeX and uses biblatex/biber. With a TeX
distribution installed:

```sh
latexmk -xelatex main.tex
```

The committed [figures/](figures), [captions/](captions), and [tables/](tables)
let the PDF build without running any notebook.
